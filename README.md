# dota2bets

Анализ про-матчей Dota 2 для ставок. Для пары команд (и драфта, когда он известен) считает вероятность победы,
распределение исходов серии и турнира, edge против коэффициентов букмекера и проверяет модель на истории.
Данные — OpenDota, интерфейс — локальный веб, текстовый разбор матча пишет Claude Code по досье, собранному кодом.

## Как это устроено

```
Браузер ──► python -m dota2bets web (127.0.0.1:8765)
              ├─ /api/predict, /api/series, /api/bracket, /api/backtest, /api/bets   ──► SQLite data/dota2bets.sqlite
              ├─ /api/live, /api/teams                                                 ──► кеш ──► OpenDota
              └─ /api/analyze (SSE)  ──► claude -p /analyze <досье>  ──► CLI проекта ──► SQLite
```

- **Код считает числа.** Elo команд и игроков, форма, личные встречи, мета героев, синергии и контры, комфорт
  игроков на героях → логистическая регрессия (pre-draft и post-draft) → вероятность с разбивкой по признакам.
  Серии и сетки — распределения; кэфы — edge, EV, Келли. Всё проверяется walk-forward бэктестом.
- **Claude пишет разбор.** Локальный сервер запускает headless `claude -p` с командой `/analyze` из `.claude/skills/`:
  Claude читает досье матча, при нужде дозапрашивает факты через CLI и заканчивает строгим блоком «Вердикт».
  Его оценка хранится рядом с оценкой модели, и журнал ставок показывает, кто точнее.

## Установка

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m dota2bets sync        # первичная выгрузка: ~48 000 карт, ~35 запросов, 2 минуты
.\.venv\Scripts\python.exe -m dota2bets train       # Elo, бэктест, модели: ~1,5 минуты
```

Нужен Python 3.14 и интернет. Для разбора Claude — установленный Claude Code CLI (`claude` на PATH) с активной
подпиской; API-ключ не требуется.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m dota2bets web
```

Открывается http://127.0.0.1:8765/ . Разделы: **Прогнозы** (лента дня), **Live**, **Турниры**, **Точность модели**;
разбор матча открывается из ленты или через поиск команд, журнал ставок — кнопкой в шапке.

Всё то же самое есть в CLI, таблица команд — [ниже](#команды-cli). Быстрый пример:

```powershell
.\.venv\Scripts\python.exe -m dota2bets predict "Team Spirit" "Team Liquid" --bo 3 --odds 1.6,2.3
.\.venv\Scripts\python.exe -m dota2bets predict "Team Spirit" "Team Liquid" --side radiant --picks-a "Lifestealer, Pangolier, Dark Seer, Mirana, Bane" --picks-b "Juggernaut, Storm Spirit, Centaur, Rubick, Lion"
.\.venv\Scripts\python.exe -m dota2bets analyze "Team Spirit" "Team Liquid" --bo 3 --odds 1.6,2.3 --record
```

Заметки о командах и игроках, которых нет в цифрах, кладите в [notes/](notes/README.md): досье подставит их в разбор.

## Ключи внешних сервисов

Без ключей всё работает: прогнозы, разбор драфта, рынки и журнал от них не зависят. Ключи добавляют эталонную
линию, быстрые живые матчи и уведомления. Задаются переменными окружения и в репозиторий не попадают.

| Переменная | Что даёт | Где взять |
|---|---|---|
| `ODDSPAPI_KEY` | расписание с эталонной линией, история кэфов для проверки модели | oddspapi.io |
| `STEAM_API_KEY` | живые матчи без задержки: пики, баны, счёт серии, золото | steamcommunity.com/dev/apikey |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления о сериях, где политика предлагает ставку | бот у @BotFather |

```powershell
[Environment]::SetEnvironmentVariable("ODDSPAPI_KEY", "ваш ключ", "User")
```

После этого откройте новый терминал и перезапустите сервер. Первый запуск с ключом OddsPapi: `book status`,
`book fixtures --days 3`, `book sync`, `book history --days 120`, `book backtest`. Если в `book fixtures` у команды
стоит «команда не найдена в базе», добавьте строку в `notes/aliases.csv`: `название во внешнем источнике,team_id`.
Без ключа историю кэфов можно импортировать из CSV со столбцами `date,team_a,team_b,odds_a,odds_b,close_a,close_b,bookmaker`.

## Интерфейс

Одна страница без сборки и зависимостей, сделана по макету редизайна: верхнее меню, на телефоне — нижняя панель.
Шрифты Unbounded, Manrope и JetBrains Mono лежат в `dota2bets/web/fonts/` и отдаются сервером, интернет для них
не нужен. Команда A всегда синяя, команда B оранжевая, акцент — лаймовый.

| Экран | Что на нём |
|---|---|
| Прогнозы | Вчера, сегодня, завтра; фильтры по формату, турниру и уверенности данных; «Матч дня» с объяснением и рекомендацией; остальные серии списком; сыгранные — с пометкой «верно» или «мимо» |
| Разбор матча | Вкладки: Обзор (разбор Claude, что повлияло, исходы серии, ключевые игроки, рынки), Составы, Драфт, Все рынки, Личные встречи, Ставка (кэфы BetBoom, рекомендация во флетах, запись в журнал) |
| Live | Карты в эфире, шанс выиграть карту по минуте и золоту, график изменения прогноза, драфт, что повлияло |
| Турниры | Серии за 30 дней по турнирам, расписание, расчёт серии, сетка турнира |
| Точность модели | Точность, калибровка, log loss по месяцам, история прогнозов, метрики для специалистов, проверка на кэфах |
| Журнал | Политика ставок, закрывающие кэфы, сегменты, записи |

История прогнозов и пометки «верно / мимо» строятся по оценкам walk-forward: модель в тот день этих матчей не
видела. График на экране Live копится, пока страница открыта: сервер сохраняет снимок при каждом обновлении.

Прямые ссылки: `#feed`, `#live`, `#tournaments`, `#accuracy`, `#journal`, `#match/<id A>/<id B>`,
`#match/<id A>/<id B>/bet` (или другая вкладка) и `#match/<id A>/<id B>/map/<герои A>/<герои B>/radiant`.

## Боковые видео в разборе матча

На экранах шириной от 1600 px по бокам разбора идут фоновые ролики без звука: слева нарезка мыла, производство
конфет и гидравлический пресс (переключаются кнопками под роликом), справа геймплей Subway Surfers. Кнопка «Фон»
в шапке разбора и крестик под роликом включают и выключают панели, выбор запоминается в браузере.

Ролики встраиваются плеером YouTube, нужен интернет. Свой набор задаётся файлом `notes/rails.json`, образец —
[notes/rails.example.json](notes/rails.example.json). Три типа элементов:

| Тип | Поля | Что показывает |
|---|---|---|
| `youtube` | `id`, `title`, `aspect` (`16:9` обрезается по бокам, `9:16` вписывается целиком) | ролик YouTube по кругу |
| `video` | `src` — имя файла из `data/media/` или ссылка | свой файл mp4 или webm по кругу |
| `ad` | `image`, `link`, `title`, `text`, `label` | баннер со ссылкой вместо видео |

## Лента прогнозов

Раздел **Прогнозы** открывается первым. Расписание ведётся руками в разделе «Турниры»: вставьте строки вида
`Team Liquid vs Yakult Brothers bo3 1.25 3.80`, формат и кэфы необязательны. Серии, которые уже идут по базе,
появляются сами после синхронизации, со счётом и составом последней карты.

По каждой серии показывается вероятность, распределение счёта, вердикт словами, надёжность данных и
рекомендация во флетах. Без кэфов рекомендация условная: «ставить на A при кэфе от 1.70». С кэфами — конкретная:
«СТАВКА: 1 флет на A по 2.10» или «ПРОПУСК» с причиной. Флет по умолчанию 1 % банка, максимум 2 флета.

```powershell
.\.venv\Scripts\python.exe -m dota2bets schedule add "Team Yandex vs MOUZ bo3 1.20 4.30; BetBoom Team vs OG"
.\.venv\Scripts\python.exe -m dota2bets forecast
```

## Разбор драфта

Когда заданы все десять героев, под оценкой появляется разбор:

- **Пики.** Кто играет на герое, сколько карт и побед, личный GPM и KDA против базы героя, последние пять карт,
  давность, статистика с пабами и ярлык от «сигнатурного» до «слабого».
- **Линии.** Перевес к 10-й минуте по золоту и опыту: сила героя на этой линии плюс уровень игрока.
- **Время.** Средний винрейт героев каждой команды в коротких, средних и затяжных картах.
- **Пары.** Лучшие и худшие синергии и контры с числом карт.

Героев можно назначить игрокам вручную; по умолчанию назначение идёт по опыту на герое. Прямая ссылка с
драфтом: `#match/<A>/<B>/map/<id героев A через запятую>/<id героев B>/radiant`.

Рядом с прогнозом на карту показывается «чисто пик» — оценка одного драфта без команд и игроков, и на сколько
пунктов команды и игроки сдвигают прогноз. Сам по себе драфт угадывает 54 % карт, так что это справка, а не
повод для ставки.

### Стадии игры

Во вкладке «Драфт» карточка «Стадии игры» отвечает на вопрос, к какой минуте одной из сторон нужно закрыть карту.
По каждому герою — винрейт до 30-й минуты и после 40-й и ярлык: лейт, темп или ровный. По каждому драфту —
профиль (лейт-драфт, темподрафт, ровный), а по карте — ожидаемая длительность и вероятность закончиться в каждом
отрезке, перевес по героям в этом отрезке и матчапы, у которых знак меняется между короткой и длинной игрой
(например, герой выигрывает пару до 35-й минуты и проигрывает после). Тот же блок попадает в досье, и разбор
Claude обязан сказать, что случится, если карта затянется.

## От кого зависит игра

Под каждым прогнозом — разрез по игрокам: на ком держится команда, кто слабое звено, кто недавно в составе, у кого
личный спад формы. В разборе матча, вкладка «Составы», к этому добавлена таблица по всем десяти игрокам.

Спад считается по последним восьми картам против обычного уровня игрока и только относительно партнёров: когда
просела вся команда, это отмечается одной строкой. Выборка мала, поэтому спад — повод проверить, а не факт.

Болезни, замены в день матча и конфликты в базе не видны. Их источники: ваши заметки в `notes/players/` и
`notes/teams/` и разбор Claude, который ищет новости о составах и указывает источник.

## Рынки

| Рынок | Как считается | Как задать |
|---|---|---|
| Победа в серии | распределение счёта из вероятности карты | по умолчанию |
| Победа на карте | вероятность карты; после драфта — с героями и стороной | `--market map`, на странице «Рынок: карта» |
| Тотал килов на карте | регрессия по темпу команд, уровню игры и героям | `--mkt kills:48.5:1.85,1.90` |
| Длительность карты | то же по длительности | `--mkt dur:38.5:1.80,1.95` |
| Тотал карт в серии | счёт серии с поправкой на третью карту | `--mkt maps:2.5:2.20,1.62` |
| Фора по картам | счёт серии | `--mkt hcp_a:1.5:2.30,1.57` |

Формат `рынок:линия:кэф_да,кэф_нет`; «да» — больше или фора прошла. Линию и кэфы можно опустить — тогда
линия берётся у медианы прогноза, а рекомендация называет минимальный кэф. На странице рынки показаны под
оценкой модели в разборе матча, вкладка «Все рынки», каждый можно записать в журнал; журнал сам рассчитает результат.

Для серии, которая уже идёт, счёт и номер карты берутся из базы. Ставка на карту до драфта помечается:
после пиков её нужно пересчитать с героями и стороной.

## Кэфы и проверка на рынке

Ставки делаются в BetBoom, его кэфы вводятся вручную. Эталонная линия (по умолчанию Pinnacle) подтягивается из
OddsPapi по ключу и нужна для трёх вещей: справедливая цена под каждым прогнозом, автоматическое расписание,
проверка модели на истории. Как задать ключи — [выше](#ключи-внешних-сервисов).

`book backtest` отвечает на главный вопрос: точнее ли модель линии на закрытии, какая доля линии в смешивании
лучшая и что дала бы политика на истории, с разрезом по формату, тиру и силе фаворита. Раздел «Точность модели»
показывает то же самое.

## По ходу карты

В разборе матча, вкладка «Все рынки», блок «По ходу карты» пересчитывает вероятность по минуте и перевесу по золоту и даёт
справедливый live-кэф. На 20-й минуте log loss модели 0.45 против 0.62 у предматчевой оценки.

## Стратегия ставок

Модель сама по себе линию сильного букмекера не обыгрывает: её log loss 0.645 против ожидаемых 0.60–0.62 у
закрывающих линий. Поэтому журнал работает как **бумажная торговля**: каждый прогноз записывается с открывающими
и закрывающими кэфами, деньги не ставятся, а отчёт показывает, где модель линию бьёт, а где нет.

Политика (настраивается в журнале и через `bets config`):

- смешанная вероятность = 70 % implied букмекера без маржи + 30 % модели;
- ставка только при edge смешанной p ≥ 4 п.п., формат не bo1, состав не устарел, вердикт Claude не «низкая»;
- размер — Келли на четверть, не больше 2 % банка.

Отчёт `bets report` даёт точность модели, смешанной p, Claude и букмекера, ROI политики и разрез по сегментам:
тир, формат, смена состава, размер edge. Правило: деньги ставятся только в сегменте, где после 200+ записей политика
в плюсе и модель точнее линии. Сегмент, где преимущество ожидается по построению модели, — смены состава и стендины.

```powershell
.\.venv\Scripts\python.exe -m dota2bets bets record "Team Spirit" "Team Liquid" --bo 3 --odds 1.6,2.3   # бумага
.\.venv\Scripts\python.exe -m dota2bets bets close 7 --odds 1.55,2.45                                # закрытие
.\.venv\Scripts\python.exe -m dota2bets bets settle; .\.venv\Scripts\python.exe -m dota2bets bets report
```

## Что стоит знать

- Состав берётся из последних матчей команды. Если игрок с тех пор играл за другую команду, интерфейс и досье
  помечают его как ушедшего; замену нужно указать вручную, пока новых матчей нет в базе.
- Одна пятёрка под разными тегами считается одной командой: история, форма и личные встречи следуют за игроками.
- Модель откалибрована на про-матчах 2024–2026 и не знает о болезнях, визах и внутренних конфликтах. Для этого есть
  разбор Claude и ваши заметки в `notes/`.
- Разбор на fable стоит по счётчику примерно в десять раз дороже, чем на sonnet, и вдвое дороже opus; по умолчанию opus.

## Лимиты OpenDota

Бесплатно около 60 запросов в минуту и 3000 в сутки на IP. Клиент проекта держит 50 и 2500, счётчик переживает
перезапуск, при недоступности отдаётся устаревший кеш. Первичная синхронизация идёт через SQL-explorer, где один
запрос отдаёт до 100 000 строк за одну единицу бюджета.
